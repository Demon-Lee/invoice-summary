# 按文件名管理签名

用户已于2026-10-22同意实施：图片按标签命名，支持直接放入文件夹，保留软件内导入及签字位置配置。

## 使用方式

- 唯一活动图片目录为软件旁的 `signatures/签名图片`，只扫描本层PNG/JPG/JPEG，文件名去扩展名即标签。
- 打开管理、点击刷新及打开/确认导出时扫描。新增有效图片自动加入；软件导入以所选标签加原图片扩展名保存。预览及导出在内存中统一转PNG、裁纯白/透明外围空白，不改用户放入的照片。
- 管理窗口保留蓝白主题、圆角按钮、自动隐藏滚动条，新增打开图片文件夹与刷新。导入标签默认取源文件名。
- 软件内更名同时更名文件并保留稳定ID和签字位置关联。软件内替换及删除沿用受影响位置确认。

## 外部变化

- 标签不区分大小写；不同扩展名同标签也算冲突。冲突和无效图片明确列出，跳过问题文件，不能任选一张或静默覆盖。
- 外部删除/改名清除原关联并记录待确认位置；外部同名替换保留记录ID但清除原关联。用户重新选择标签或明确选择不使用签名后解除待确认。外部改名不按笔迹/哈希猜测身份。
- 有待确认位置时停止带签名导出，仍允许用户明确选择无签名导出。导出对显示的完整配置版本和实际文件字节重新核对；变化时刷新并要求重新确认。

## 保存与迁移

- 配置升级至version2，保留items(id,label,file,sha256)、bindings，增加issues列表与attention(位置到原因文字)。sha256对应磁盘原图；快照包含归一化后的PNG字节。
- 旧version1配置及UUID图片保留备份，旧图片按标签复制到活动目录，保留ID与四处关联。旧标签含文件名禁用字符时转换为合法且唯一的标签并展示说明，不覆盖已有图片。
- 配置原子写入、进程/OS锁、确认版本门禁沿用。扫描/变更中途失败保留原图及可恢复数据，不静默重建损坏配置。
- 构建先把旧个人目录复制到新构建目录，再在副本迁移；不在旧发布目录中调用会迁移的读取。个人目录中的直接放入图片和迁移备份都随软件复制，全部从公开ZIP/源码排除。
- 保持V1.1.20，无新增依赖，不改skill、识别、写表、金额、PDF定位与尺寸规则；本轮不上传GitHub。

## 检查范围

按当前开发约束只做静态审查、语法编译、构建及保存文件/归档核对；不新增或运行测试、不启动GUI/Excel、不处理业务文件。发布保留旧完整目录；旧签名原始字节、标签/角色的迁移对应关系分别检查，不能仅以新旧目录完全相同作为迁移检查。
