# 保存只出现在签字位置

用户确认保存按钮在签字位置有用，要求签名库无用时删除并缩小界面。现有保存函数仅提交pending_bindings；图片导入、重命名、替换和删除已由各自变更任务提交。因此只在签字位置显示同一保存按钮，签名库隐藏该按钮。保存对象、草稿与文件操作不变。

签字位置的保存按钮与状态紧随两张位置卡片及必要警告显示，按钮保持右对齐，不固定到窗口底边，随页面内容滚动。签名库空闲且状态为空时收起底栏，有正在读取/保存、失败或未提交位置等状态时仅显示简短状态。统一状态更新入口同步角色页及库页的简短状态，按当前页显示；页签切换只改变呈现，不提交数据。

用户随后要求四个签字位置各自显示当前标签的签名图片，以核对标签和内容。每个下拉框下方增加固定高度的缩略预览，利用既有留白，保留原700高度上限及最小尺寸/缩放/滚动。预览跟随尚未保存的选择；不使用签名时清空，读取失败时显示中文空状态，不沿用上一个标签的图片。

沿用单个后台任务队列，增加独立的角色预览批次通道，与签名库单选预览分开合并请求/取消。每批最多四个签名，按ID去重，复用现有指纹和缩略图缓存，尺寸限200x90。后台仅返回PIL图片，Tk图片只在主线程创建；请求序号及ID/指纹快照丢弃过期结果，快速选择只保留最新待处理批次。刷新或图片替换后重新核对，关闭/变更任务取消未完成的角色预览，不新增扫描或图片写入。

版本保持1.1.22，GitHub继续等待用户明确预览批准，不推送/上传/发布。保持签名图片及配置、识别规则、engine/skill和处理流程。未请求测试，不新增/运行测试；仅静态复核、语法、构建和保存文件核对。原程序关闭后更新原目录，供用户继续预览。
