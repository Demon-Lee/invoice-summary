# 按参考截图分配明细列宽

## 用户目标

用户提供 2533×568 的表格截图，要求达到大概同样的比例。此要求替代 1.1.4 的文件名固定 250px、仅三列原生拉伸方案。依据截图内字段起点估算，以表格实际宽度为基础分配十列。

| 列 | 初始比例 | 最小宽度 px |
|---|---:|---:|
| 序号 | 2% | 44 |
| PDF → 新文件名 | 19% | 180 |
| 产品名称 | 18% | 170 |
| 规格型号 | 7% | 90 |
| 单位 | 4% | 44 |
| 数量 | 6% | 58 |
| 单价（自动） | 9% | 95 |
| 含税金额 | 11% | 100 |
| 生产厂家 | 19% | 170 |
| 人工校正 | 5% | 84 |

## 实现与交互

ui_widgets.py 新增仅负责列宽的 ProportionalTreeviewColumns；ui.py 保持原生 Treeview、字段和值、对齐、选中、双击及自动滚动。所有列 stretch=False，避免原生拉伸与比例分配相互覆盖。按 Treeview 实际宽度减 2px 安全边缘作为可用宽度；不重复减去由外框已预留的滚动条空白。

小于比例值的最低宽度先固定，再按剩余权重分配其他列。分配总宽为 max(可用宽度, 最小宽度合计)，向下取整后的余量按小数余数分配；足够宽时总宽对应可用宽度，不足时使用现有横向滚动，不挤坏表头。

Configure/Map 追加绑定，以一个 after_idle 合并布局，实际宽度未变时不重写；不修改数据、不重建行、不产生新工作线程。原生列边界拖动期间暂停自动布局，释放后等待原生 drop 完成，再将当前列宽记录为新的比例；同宽下保留原生拖动结果，后续窗口缩放继续按该比例。比例仅本次软件会话有效，重启恢复截图比例。不新增设置或恢复按钮。

销毁时取消唯一待执行回调，原 Treeview 的绑定和双击操作继续执行，不返回 break。手动拖动遵循最小宽度约束；仅点击边界、实际列宽未变时不更新比例。
