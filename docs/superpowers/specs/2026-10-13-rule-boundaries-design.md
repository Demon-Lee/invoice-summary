# skill 与软件的功能归属和更新边界

用户已批准三类分工：skill 共享识别与核对规则、软件独有交互及整批重填、双方共同遵守的数据与模板约定。继续沿用整文件夹分发。

## 单一边界定义

新增应用自有 `policy.py`，集中声明共享文件白名单、接口版本、软件策略版本、功能归属说明和更新范围展示名称。此文件随软件升级，不能被 skill 更新包替换。人工校正、清空重填、完成提示和中断恢复仍使用原软件实现；不修改原 skill。

原始 skill 文档完整保留，作为共享规则来源参考。它的对话执行、回复格式、增量匹配写表约定不成为软件操作指令。软件流程为识别 → 可选人工校正 → 重新检查 → 正式执行时清空整批重填 → 共享写后核对。

## 兼容性

- 新导出包采用清单格式 2，声明作用范围 `shared-invoice-rules`、数据接口版本 1 和工作簿约定版本 1；这些声明计入版本哈希。
- 继续读取格式 1 的既有快照和更新包。它们仍需通过原文件校验、当前软件自带写表组件指纹及接口检查；不自动宣称未知语义兼容。
- 活跃、同步、导入、回退及便携构建都以软件自带的共享模板约定指纹为支持依据，不能让活跃快照自行扩展软件能力。
- 原 skill 的写表组件只记录指纹，不执行、不随更新包复制。该文件变化时要求维护者核对共享约定并升级软件，保留软件的人工校正和清空重填策略。只改文档无脚本适配的门禁保持。
- 指定字段、声明和入口检查只能识别已定义的兼容条件，不能自动判断任意算法改动的语义；预览与逐分校验继续保护业务执行。

## 展示与发布

“规则与更新”中默认展示功能归属；另有本次更新结果和明确标注为来源参考的原始 skill 说明。同步、导入、回退报告显示受影响的共享功能和软件功能保留情况。相同边界说明随软件发布成文本文件，使用说明及 README 同步更新，版本 0.1.6。

遵守开发约束：不新增或运行测试，不启动 GUI、更新接口检查或业务流程；只做独立只读审查、构建和发布文件检查。
