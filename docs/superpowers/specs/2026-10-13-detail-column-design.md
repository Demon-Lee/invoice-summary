# 明细列宽修正

## 用户目标与原因

用户要求全屏时 PDF → 新文件名列不要挤占其余明细字段。当前只有 filename 设置 stretch=True，Treeview 将窗口增加的全部可用宽度分给这一列，其他列保持初始宽度。

## 方案

沿用已批准的明细表界面，文件名默认 250px 且不自动拉伸；产品名称、规格型号、生产厂家共同分配窗口增加的宽度。这三列最小宽度分别为 170、110、175px，避免缩小窗口时压缩为 40px。其余列维持原宽度、对齐方式及手动拖动列边界能力。窗口不足时使用现有自动隐藏横向滚动条，完整值继续保存在原表格中，用户可拖宽文件名列查看。

仅固定全部列会让宽屏剩余区域空置；额外窗口宽度按比例分配需要新的尺寸事件处理。选择原生 stretch 分配三项文本列，保持变化范围小且保留原生列宽调整。

软件升为 1.1.4，更新用户说明、构建和原发布文件夹。App、ui_widgets、共享 engine、skill、写表和校正逻辑不改。当前规则 6b9e6cdafb3f、上一版 42334e9f238e 保留。若原发布目录仍不存在，从已核对的 1.1.3 Windows ZIP 恢复规则到忽略目录用于构建。
