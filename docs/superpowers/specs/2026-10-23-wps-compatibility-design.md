# Excel / WPS 桌面兼容

用户要求软件兼容 WPS，提供目标版本12.1.0.29161、32位，并授权实际尝试；后续明确要求默认优先WPS，无可用WPS时再选择Microsoft Excel。两种软件使用相同识别/校正/填表/完整显示/分页/导出/签名流程。仅在激活阶段选择软件，操作已经开始后不切换提供程序。开发验证可显式指定Excel或WPS，界面不增加新的设置项。

本机同版WPS已完成独立进程启动、混合字体、自动行列调整、公式缓存、A4横向导出及逐单元格PDF完整性验证。合成样本覆盖单页、多页以及临界末尾分组；四处模拟签名加入PDF后仍通过完整性校验。测试输入/脚本/PDF均在忽略目录，原用户表格、发票和签名库未改动。应用名称返回Microsoft Excel且Version返回12.0，实际进程为et.exe、产品版本12,1,0,29161；因此按原生窗口所属进程识别提供程序，不使用Application.Name判断。

## 应用边界

新增软件自有PowerShell运行时负责激活、实际软件识别、独立实例确认和清理。记录调用前已有进程，只有新建进程、正确进程名、有效窗口句柄和零个工作簿时才接受；无法证明独立实例则停止，不隐藏、关闭或杀死既有应用。看门狗只操作记录的进程ID/启动时间/名称匹配的自有实例。

识别规则和engine原文件保持不变。字体处理继续使用当前规则快照中的同一脚本；软件先解析其AST，要求唯一且静态的New-Object -ComObject Excel.Application创建语句，只替换该创建入口以注入已经确认独立的应用实例，其余语句原样执行。脚本形态不满足约定时明确拒绝，不降级为另一套字体规则。检查、字体、排版及导出每阶段都使用选定提供程序；Excel现有排版/PDF验证算法继续保留。

Python保留ExcelAdapter类名以兼容已有调用，增加Auto/Excel/WPS提供程序参数和激活结果验证。界面及错误摘要使用Excel/WPS或表格软件称谓。格式、公式、PDF逐单元格完整性、尾部同页、签名只在PDF出现及双PDF发布/恢复条件保持相同要求。

实际模板试验发现已发布1.1.22也会发生的PDF坐标校准错误：0.84pt相隔的成对边框路径被0.8pt旧阈值分开，重复短路径又会偏移均值。为完成实际模板兼容验证，软件pdf_layout.py的边框聚类单独改为1.0pt并取路径范围中点；不改变文字0.75pt裁切容差、全部表头精确匹配或逐格完整性检查。此项属于软件PDF验证，不写入共享规则。

## 交付和验证

本地候选版递增至1.1.23，与已发布1.1.22区分。先执行新增单元测试的失败/通过周期，再用实际WPS及Excel的临时文件验证，并检查多页、临界末尾分组、签名、公式和值/合并结构保持、私有实例和文件清理。构建后核对保存文件及公开压缩包，整个signatures目录及业务文件不进包。仅更新本地，GitHub发布需用户后续指令。
