# 列宽允许自动扩大和缩小

用户明确要求取消原列宽下限，允许按内容撑大和缩小；沿用当前1.1.23本地候选，不上传GitHub。执行处理和PDF导出共用同一个原生排版函数，修改同时适用这两阶段；行高继续保留原下限。字体、值、公式、合并、识别、金额核对和签名数据不改动。

方案比较：仅删除原列宽下限最简单，但临时副本试验证实标准领用模板的F15日期标签会被遮挡；推荐先用原生AutoFit拟合表头/明细/合计，再按未合并标题和页脚实际内容计算必要宽度。保留整列原宽或写死另一组列宽都会阻止按当前内容缩小，故不采用。

列宽不再参考旧模板数值。对范围外的非空文字单元格，用其原生单格AutoFit测量所需宽度，再恢复该列已经按明细计算的宽度。若标题/页脚文字可在既有caption_spans内显示，仅在该跨度总宽不足时扩大跨度最后一列；单格则取内容所需宽和当前明细所需宽的较大者。合并标题保持，后续逐格PDF检查仍保证未被裁切。

四处固定签字标签需要空白书写位置，在其现有跨度内额外保留约三个汉字（按当前字号换算）的书写宽度及边距；它属于模板内容需要的空间，不采用原列宽作下限。日期及说明按各自实际文字拟合。原生最大列宽255限制、行高下限、公式快照和内容不变检查保留。宽度不足仍拒绝导出，不放宽PDF完整性检查。

验证沿用用户已授权的WPS兼容临时副本试验：标准少量明细、实际多票批次和模拟签名，检查列宽能缩小也能扩大、行高下限、内容/公式、页脚及PDF完整性、源件不变。所有试验材料在忽略目录。构建和替换前核对规则、私人签名及受保护文件；旧目录和包归档，程序正在运行时停止替换。
