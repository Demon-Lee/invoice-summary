# 发票汇总助手设计

用户已认可 Windows 离线桌面版，并接受安装 Microsoft Excel。新增要求：识别流程和原则与 summarize-invoice-pdfs skill 对应，skill 更新后软件可同步更新。

## 产品与输入

- Windows 10/11 桌面程序，要求安装 Microsoft Excel 桌面版。
- 选择一个包含完整批次发票的 PDF 文件夹和一个现有 `.xlsx` 工作簿；使用“验收”和“领用”两张表。
- 主界面包含路径选择、只读预览、执行处理、打开结果位置、同步 skill、导入离线更新包、识别版本和运行结果。
- 预览表逐明细展示序号、原 PDF → 新文件名、规格型号、单位、数量、含税金额；结果说明同时提供产品名、生产厂家、金额核对和异常信息。
- 首版不提供 OCR；无可解析文本层的 PDF 停止并显示异常，与现有 skill 对应。

## 实现与来源

- Python 3.12、tkinter/ttk、pdfplumber、openpyxl；PyInstaller 打包为可解压双击使用的 Windows 程序。
- 使用 skill 的 `scripts/invoice_pipeline.py` 作为识别和命名规则唯一来源，不复制实现一套新解析器。
- 使用 skill 的 `scripts/collect_excel_totals.py` 和 `scripts/apply_mixed_fonts_excel.ps1` 进行结果收集及 Excel 字体与重算处理。
- 现有 Node 写表器依赖的 `@oai/artifact-tool` 许可证限定内部评估且禁止分发，软件不包含该组件。软件使用 openpyxl 实现同一写表约定。
- 软件源代码放在独立的 `invoice-desktop` 目录和独立 Git 仓库，发票和现有工作簿不作为项目资产。

## 流程与门槛

1. 检查输入扩展名、目录、工作簿可读性及 Excel 可用性。
2. 调用固定版本识别脚本生成只读预览；依据 PDF 内容排除查验报告。
3. 在内存中验证明细、逐票金额、数量、重名冲突和工作簿写入计划；检查唯一表头和“合计—签字—说明”三行页脚、日期标签和字段映射。
4. 展示计划、金额、已有发票和异常；存在未解决异常时禁用执行。
5. 执行前重新检查文件指纹和目录成员，任何预览后变化都要求重新预览。运行期间固定识别版本。
6. 用户启动执行后按 skill 顺序重命名、原位写表、Excel 字体及重算、收集总计、逐分验证。
7. 只有每张票的价税合计、明细合计、验收序号金额，以及批次总额和两表页脚金额均相同才显示成功。不能仅凭脚本退出码认定成功。
8. 不自动创建发票或工作簿备份，不覆盖重名目标、不猜测字段、不自动修模板；所有当前运行临时报告均清理。若执行中失败，展示已经执行的步骤及实际状态。

## 工作簿约定

- 保留相同序号、产品、规格的重复明细及原始顺序；空数量按 1，零或非数值数量阻塞。
- 验收单价保留 `=金额单元格/数量单元格`；领用对应七个字段写值，生产厂家不复制。
- 保留模板样式、内部空行、备注、页脚三行的单元格和行高、合并单元格、打印区域。扩容与收缩明确移动页脚并重建总计公式。
- 只删除最后一个有内容数据行后至页脚前的连续空行；任何列的文字、值或公式均视为内容。
- 两表签字日期采用正式写入时读取一次的本机日期 `YYYY.M.D`。
- 已有行与同一明细出现不同的业务值、工作簿已有发票不在完整目录中、结构不符合约定时停止，不覆盖冲突。

## skill 同步

- 软件版本与识别引擎版本分开；引擎版本由白名单文件内容散列生成。
- 内置经过验证的识别快照。可绑定本机 skill 目录并检测变化；同步时保存不可变版本快照并原子切换，下次处理使用新版本。
- 其他电脑通过离线 ZIP 更新包同步；校验格式版本、白名单、大小、路径、SHA-256、解析入口和依赖兼容性，拒绝路径穿越或不兼容更新。
- 更新对象包含 `SKILL.md`、识别脚本、总计脚本及字体脚本。记录原 Node 写表脚本的散列作为写入原则兼容标记；该脚本变化时需要升级软件写入器，不悄悄宣称兼容。
- 只修改 `SKILL.md`、未修改相应脚本时，提示规则待适配并阻止同步。同步对比版本并显示修改文件，保留上一个软件引擎版本以供回退；这些是软件资源，不是发票备份。
- 新增当前安装包未包含的 Python 依赖时提示需要升级主程序。散列证明内容完整性，不代表第三方来源可信；只导入用户可信的 skill 更新包。
- 开发者更新 skill 后同步维护脚本及测试，使用软件项目的导出工具生成离线包。自然语言规则不会自动编译成程序。

## 验收

- 基于现有 skill 的 Python 测试验证解析行为；新增有意义的工作簿和流程测试覆盖重复明细、异常停止、冲突保护、扩缩容、页脚、指纹变化、失败状态和更新包校验。
- 用临时输入验证 Excel 字体/重算/总计复核完整链路；保留真实原始文件不变的证据。
- 打包后检查程序启动、内置引擎读取、离线环境和运行依赖；交付可运行程序、源码、使用说明和更新工具。
