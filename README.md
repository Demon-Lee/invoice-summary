# 发票汇总助手

Windows 离线桌面软件，使用 summarize-invoice-pdfs 的识别脚本与规则快照。电脑须安装 Microsoft Excel 桌面版。

**当前版本 1.1.21：填表后使用Excel原生自动列宽统一适配所有明细列，保留模板列宽及行高下限；导出时让最后一条明细与合计、签字、说明保持同页，空间不足则整组移至下一页。PDF仍为A4横向、所有列一页宽，并检查实际导出的文字。PDF 导出仅在本次执行处理并通过金额核对后启用。普通使用者完整解压后即可使用随包规则，无需安装或同步 skill。规则由维护者在维护环境准备，随完整软件包分发。**

首次选择文件夹／工作簿时，阶段卡和底部状态显示“等待只读预览”；只有本次软件会话已经完成过预览，之后更换输入或结果失效才显示“需要重新预览”。

界面采用简洁商务风：顶部常驻执行步骤和必要条件，白色分区、蓝色主要操作、四项批次摘要、交替底色明细及校正标记。右上角显示实际软件版本 `V1.1.21`，随版本更新自动变化；界面直接显示发票处理页。阶段卡只显示左对齐、上下居中的加粗标题，通过颜色区分结果；简短原因见弹窗，技术诊断可在异常弹窗按需复制。

输入区域左侧为“选择 PDF 文件夹”和“选择目标工作簿”圆角图标按钮，预览前蓝色高亮，可重复选择。预览通过后直到 PDF 导出成功，路径框锁定、按钮改为描边，仍可点击原按钮，确认后重新选择；只有实际选择不同路径才清除预览／校正／导出资格，取消或选择原路径保留当前结果。预览异常／无需处理或 PDF 导出成功后恢复路径编辑。后台处理和选择窗口期间两个选择入口均禁用。

1.1.7 起，主要操作使用独立圆角按钮、可见边框、本地图标和悬停／按下反馈。“只读预览”固定浅蓝描边，“执行处理”可用时深蓝实心，禁用时浅灰描边；两者不再交换强调色。运行时相应按钮显示“正在预览…”／“正在处理…”。键盘焦点清晰可见，人工校正及重新预览时清除校正的提醒继续保留。

1.1.12 起，主操作为“只读预览、执行处理、导出 PDF”。三个打开入口集中在操作按钮下方，使用加大的高对比文件夹／表格／导出文件夹图标及完整文字。空路径对应入口禁用，导出目录在成功导出后可打开；处理中暂不可打开。独立人工校正按钮已移除，预览有可校正明细时，表格标题旁以浅金背景、铅笔图标和加粗文字提示“双击明细，可人工校正”；恢复未完成任务或预览失效时显示暂不可校正。

明细表头和所有内容统一左对齐，包括序号、单位、数量、单价、金额及校正标记。列宽按参考截图的比例随窗口缩放：宽度足够时，文件名约 19%、产品名称约 18%、规格约 7%、厂家约 19%，其他空间分给序号、单位、数量、单价、金额和校正标记。每列有最低宽度；较窄窗口可横向滚动。拖动表头列边界可自行调整，调整后的比例在本次软件会话的窗口缩放中保留；重启恢复默认比例。预览保留完整原值。

明细和报告采用自动隐藏圆角滚动条：内容溢出时，鼠标移入或滚动会显示，停止活动约 1.4 秒后隐藏；悬停滑块或拖动时保持可见。滑块位于固定空白边缘，显示／隐藏不改变内容区域。底部保留约 3px 的浅色细线轨道，处理中显示平滑蓝色渐变流动，结束时停止；实际步骤与结果继续由状态文字、阶段卡和完成提示说明。

## 执行步骤

1. 完整解压发布包，双击 `InvoiceSummary.exe`。
2. 选择完整批次的 PDF 文件夹和目标 `.xlsx` 工作簿。
3. 点击“只读预览”，核对文件名、明细、金额和异常；解决异常后重新预览。
4. 预览通过后点击“执行处理”，清空旧明细并按完整批次重填，等待完成。
5. 等待主页面显示“执行处理完成”；金额复核或临时文件清理有问题时会弹窗。开始下一批处理前再重新预览。
6. 需要 PDF 时，点击“导出 PDF”，选择保存位置，完成后点击“打开导出目录”。

1.1.8 起，随包共享规则在编号前按 PDF 全部页面的文本分类。只有明确识别的验收／领用表、送货／出入库单等非发票文档才自动跳过；查验报告也仅作跳过说明。跳过文件保持原样，不占序号、不填表、不计发票数量或金额。存在跳过文件时仍弹出提醒，列出跳过数量及完整文件清单，较长内容可滚动查看。扫描件、损坏文件、类型不明或疑似发票字段缺失仍阻塞，不能通过跳过解析失败来放行。无可处理发票时禁止执行，保留工作簿。分类属于 skill 共享规则，清单展示属于软件；需要识别改进时获取维护者发布的新版软件包。

1.1.9 起，正式写入时，“领用日期”为本机当天，“验收日期”为前一个日历日，日期格式为 `YYYY.M.D`；只读预览不会保存日期。

**执行会重命名 PDF，清空两表全部旧明细（含品牌、备注）后整批重填；原位更新，不自动创建备份。**

## 必要条件

- Windows 10/11，已安装 Microsoft Excel 桌面版；软件离线运行，无需安装 Python 或 Node.js。
- 完整解压整个软件文件夹，保留 `InvoiceSummary.exe`、`_internal` 和 `recognition`。
- 有文本层的电子 PDF；每次选择完整批次，不支持扫描图片 OCR。目录中没有的旧明细将移除，旧表人工修改不会保留。
- `.xlsx` 含“验收”“领用”两表，以及约定的表头、明细格式行、日期标签和唯一“合计—签字—说明”三行页脚。
- 执行前关闭 Excel 中的目标工作簿；软件和输入文件所在目录须可写。

软件处理页顶部直接显示“执行步骤”和“必要条件”，发布包内的使用说明.txt提供详细操作说明。1.1.14起移除“使用说明”选项卡、执行步骤下方的整行处理提示和明细标题旁的说明文字；预览后的双击校正提示继续显示。

## 阶段完成提示

七个按钮继续共用一行：只读预览、执行处理、导出PDF为工作流程，签名管理及三个“打开”按钮为辅助功能。两组之间用留白和竖分隔线区分；分组边界换行时改用横线。窄窗口按完整按钮尺寸自动换行，不缩短文字。

操作按钮下方的阶段卡显示当前阶段与结果，大标题保持左对齐、上下居中：蓝色为处理中，绿色为通过，黄色为预览异常或清理提醒，红色为操作未完成。只读预览、执行处理及PDF导出顺利完成后仅更新主页面，不再弹出完成提示；异常及需要注意的情况仍弹窗，可复制完整诊断。

预览有异常时明确提示暂不能执行，执行失败时显示失败原因；填表成功但临时文件清理未完成时单独提醒。人工校正检查正常时只更新页面，有异常时弹出中文原因及诊断复制按钮。更换输入或更新规则后，旧的完成提示清除，需要重新预览。

主页面不再设置详情入口或报告区域，空间用于发票明细。异常弹窗显示简短中文原因与处理建议，点击“复制错误信息”可复制该次提示对应的原始错误、金额核对和处理记录，便于反馈排查；正常完成仅更新主页面阶段卡、指标及明细，不再弹窗。跳过的非发票文件清单可在结果弹窗中完整滚动查看。阶段大标题及细线进度条保留。

报错、提醒、确认、校正、签名和导出设置窗口统一以当前主窗口为居中参考，最大化时仍采用相同策略；原生文件/文件夹选择和名称输入也使用统一定位。位置限制在主窗口所属显示器的可用区域，弹窗打开后可自行移动。

## 导出 PDF

1.1.10 起，独立的“导出 PDF”按钮分别生成 `验收单.pdf` 和 `领用单.pdf`。默认保存在工作簿同级的 `导出PDF` 子文件夹，可更换位置；同名文件须确认后才替换。导出完成后阶段卡显示“PDF 导出完成”，点击“打开导出目录”可查看文件；不再单独弹出成功提示。

- A4 横向，所有实际内容列缩放到一页宽；行数较多时向下自动分页。标题、签字／说明、备注和右侧模板文字均包含在打印区域，忽略只有格式的远端空单元格。
- 1.1.13 起，只有**本次执行处理并通过逐票及批次金额核对**后才能导出。仅选择文件、完成预览或人工校正均不会启用；执行失败或无需处理也不会启用。更换输入、重新预览、已使用规则更新或重启软件后，须重新预览并执行成功。
- 导出前确认工作簿仍与本次处理完成的版本一致。外部修改或文件丢失时停止导出，并要求重新预览、执行；普通导出失败可重试，成功后可重复导出，取消导出也保留本次资格。导出本身不重新核对发票金额；金额已通过但临时文件清理有提醒时仍可导出。
- 在临时副本中设置打印参数，通过本机 Excel 生成 PDF；临时分页不保存回原工作簿。填表时使用Excel原生自动列宽适配表头、明细与合计数字，保留原有字体、数字格式及模板行高下限；达到列宽上限时启用换行。页边距及重复表头保留；未设置重复表头时补充标题至表头行。
- 1.1.21原号优化后，明细及表头区域采用未合并的标准模板，标题和页脚合并保持。容量不足或错误值会停止发布排版副本。从最后实际明细到最终说明作为同页组，最多额外缩小约5%，仍不足则整组移至下一页；超过单页容量时停止导出。两份PDF均逐格检查实际文本及分页，签名添加前后均检查。
- 1.1.11 起，优先在本次独立 Excel 中使用已安装的 Microsoft Print to PDF 进行分页，避免部分第三方虚拟打印机造成纸张放大；结束时恢复 Excel 原打印机，不更改 Windows 默认打印机。没有可用的 Windows PDF 打印组件时沿用原组件，仍严格检查实际页面尺寸，异常会列出尺寸及处理建议。
- 两份 PDF 均生成并检查后才发布；替换失败时恢复已有文件，恢复不完整时保留备份并报告具体路径。导出失败不清除当前预览或人工校正。
- 此功能由软件维护，随完整软件版本更新。

## 签名图片与标签

签名管理使用白色扁平页签导航，蓝色文字、浅蓝背景和底线标识当前页，默认打开“签字位置”。验收单、领用单各一张卡片，每张卡片并排设置两个签字位置；字体、字段和配色与主界面统一。点击“签名库”里的“打开签名文件夹”，将 PNG/JPG/JPEG 放入软件旁的 `signatures/签名图片`；文件名去扩展名即标签。打开管理或点击“刷新列表”后自动识别，也可通过软件导入。四个签字位置选择对应标签后，点击“保存”才生效；右上角关闭不保存未提交的位置选择。切换选项卡保留草稿与各页滚动位置，不额外扫描或保存；两个页面沿用自动隐藏滚动条，默认页也显示已有警告。签名只添加到导出的 PDF，原 Excel 不添加图片。

软件内更名保留位置关联；外部改名、删除或同名替换会标出需要重新确认的位置，重新选择标签或明确选择不使用签名后才允许带签名导出。不同扩展名的同名文件也算标签冲突，会列出原因而不会任选一张。无效图片跳过并提示，直接放入的原图不会被裁写。

旧签名库自动复制迁移，保留旧配置/UUID图片备份和角色关联。个人转移时复制整个软件文件夹；公开分发 ZIP 排除整个 `signatures` 目录，不包含个人签名或备份。

签名管理通过单个后台任务队列读取、刷新和生成缩略图，过时预览会丢弃；刷新保留列表选择及滚动位置。相同内容的图片处理结果仅在内存中缓存，PNG/缩略图缓存最多16MiB、32项，已验证指纹最多256项。缓存按当前原始文件SHA256使用，预览和带签名导出仍读取实际字节并核对；不生成额外的个人图片缓存文件。

## 人工校正

只读预览完成后，双击需要校正的明细，或选中该行后按 Enter。对照原 PDF 修改产品名称、规格型号、单位、数量、含税金额和生产厂家；单价自动计算。弹窗同时显示原识别值和当前值，支持“打开原发票”和“恢复识别值”。双击表头或空白不会打开校正窗口。

点击“保存并检查”只更新本次预览；软件重新检查金额、改名碰撞与工作簿模板，通过后才允许执行。校正过的明细会高亮，检查结果记录修改前后值。正式重填使用本次预览及校正后的全部明细。

这是软件本地功能，不修改或训练 skill。只能校正已有明细字段，不能增删明细、改序号或修改票面总额；漏项、多项和整票解析失败仍需改进 skill。数量空白按 1，非空须为有效非零数字；名称、生产厂家不能为空，规格和单位可空。校正后的每票明细合计必须仍与原票面总额逐分一致。

校正只对本次预览有效；重新发起普通预览会重新识别，需要再次校正。执行中断时校正随本机恢复记录保留，核对 PDF 哈希和识别版本后恢复；恢复期间先完成上次运行，再进行新的人工校正。记录不会随软件目录分发。

1.0.0 起，有校正时预览按钮明确提示“清除校正”；重新预览、更换输入路径和关闭软件会针对本次校正提示确认。选择“否”保留原预览和校正。保存校正后已经自动检查，不必再次预览。恢复记录中的校正已持久保存，不误报为关闭即丢失。操作失败且原预览仍对应当前规则时保留原预览；重试执行仍会检查输入指纹、规则版本和权限。

## 完整批次重填

0.1.4 起，软件每次清空“验收”和“领用”表头之后、合计之前的主表明细内容，再按当前完整 PDF 批次连续重填。主表中的品牌、备注、其他手填内容、批注和超链接一并清除，旧名称或旧金额与识别结果不同不再阻塞。保留表头、格式、其他工作表、签字和说明页脚，按明细数量调整数据区并重新生成单价和合计。

0.1.7 起，清空范围按完整表头的最右列界定，保留主表右侧“第二联：财务报销”等模板内容。侧边文字分写在多个单元格时也保留原位置和样式；增减明细行后仍保留，保存时复验，预览报告显示保留数量。不能安全移动的右侧合并结构或跨主表／侧边的公式区域在预览中停止。旧版本已经删除的文字不会自动从其他工作簿补回，须补回文字或使用完整模板。

0.1.8 起可同步 skill 的 `template_rules.json`。新规则按主表右侧完整标识的实际结束行保留必要空白明细区，不固定为第 13 行；合计在“本次末条明细”和“最低保留行”中较晚者之后。保留空行的样式、边框和行高，空行不填假数据，合计范围包含保留区。预览显示每表最低保留行、必要空行数和合计行。若源模板合计已经位于标识结束行或其上方，停止并提示恢复完整模板，与 skill 一致。

正式发布包携带维护者已同步并选中的规则；普通用户直接使用，维护者准备规则后重新分发完整文件夹。旧快照使用原删行行为；没有匹配完整标识时按实际明细收缩。

只读预览只在内存中拟定计划，显示每表旧明细清空数量及本次重填数量，不保存原文件。正式执行使用暂存工作簿及原位替换，然后继续 Excel 字体、重算和逐分验证。即使旧表明细与本次相同，普通预览也可以执行重填；空发票批次、识别异常、金额不符、重名和模板结构问题仍阻塞。

未完成运行保留写表前哈希及写入阶段。两表已写完并完整对应预览时，恢复可跳过重复写表；如果写入阶段记录缺失且工作簿已变化，需要完整对应本次结果，否则停止等待核实。旧版本恢复记录仍可读取。

完整重填是本软件的写表策略，skill 的识别、规范化、折扣及运费处理规则保持对应；模板最低保留行声明由双方共同读取。

|---|---|---|
| skill共享规则 | PDF识别、字段规范化、折扣／运费、排序／文件名、金额验证、字体／重算和模板最低保留行 | 维护者更新兼容的脚本及声明，随完整软件包分发 |
| 软件独有功能 | 人工校正、整批重填、保留侧边模板、完成提示、中断恢复及PDF导出 | 由软件版本维护 |
| 共同约定 | 字段、精度、表头、页脚、日期及脚本输入输出接口 | 变更时检查兼容性，必要时升级软件 |

软件流程：识别 → 可选人工校正 → 重新检查 → 清空旧明细并整批重填 → 写后金额核对 → 可选导出PDF。skill原文中的对话格式、自动执行或增量填表方式不作为软件操作指令。

## 规则维护与分发

普通使用者完整解压发布包即可处理发票，保留 `_internal` 和 `recognition`。需要新版规则时获取维护者发布的完整软件包，在新目录完整解压后使用。

维护者在源码维护环境更新skill的规则、对应脚本和模板声明，使用既有 `EngineStore.sync` 等开发接口准备经兼容性检查的规则快照，再构建或准备完整便携目录并打包分发。源码中的 `tools/export_update.py` 和 `tools/prepare_portable.py` 继续供维护者使用，Windows软件内没有相应操作入口。仅修改SKILL.md不会自动生成算法；新增策略、接口、依赖或未知写表器需要先适配软件。

规则保存在软件目录的 `recognition` 中，构建保留维护者已选中的当前及上一快照。包内规则仍检查清单、路径、SHA256和软件支持约定；接口不兼容或规则损坏时停止处理。规则损坏请重新完整解压发布包或联系维护者，不再检查本机skill路径。旧版本记录的来源绑定不再读取或写入；既有业务恢复记录保留。

模板最低保留行继续使用与skill共用的 `template_rules.json`，按完整侧边标识实际结束行保留空白明细，不固定行号；旧快照沿用其既有策略。受支持声明可由维护者准备到新包，未支持的策略须适配。识别版本在只读预览报告中显示，处理期间固定使用已核对版本。

如果Excel操作或验证中断，重新选择同一批次与工作簿进行只读预览，可继续未完成流程；重启后也有效，恢复期间须保持发票内容及识别版本一致。完成验证后清除恢复记录。

移动明细和页脚时维护公式引用。不支持的动态引用、命名区域，或需要增减行时涉及表格、筛选、图表等结构，会在预览中提示调整模板。

构建时，`tools/prepare_portable.py` 优先保留现有 `release/InvoiceSummary` 中的规则；首次升级才读取旧 AppData 中兼容的规则。只复制规则白名单和清单，不复制个人路径、设置或业务记录。运行中的软件直接使用所在目录的规则，旧 AppData 规则不参与选择。

## 实现

Python/tkinter、pdfplumber、openpyxl 与 Microsoft Excel 自动化。现有 Node 写表器依赖的 OpenAI 内部评估组件不随软件分发，软件使用独立的 openpyxl 写表器执行同一模板约定。openpyxl 的行移动不会自动维护所有相关结构，因此软件明确处理页脚合并、行高、打印区域和总计公式；参考 [openpyxl 行编辑说明](https://openpyxl.readthedocs.io/en/3.1.1/editing_worksheets.html)。打包采用 [PyInstaller 的目录分发方式](https://www.pyinstaller.org/en/stable/usage.html)。
