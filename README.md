# 发票汇总助手

Windows 离线桌面软件，使用 summarize-invoice-pdfs 的识别脚本与规则快照。电脑须安装 Microsoft Excel 桌面版。

## 执行步骤

1. 完整解压发布包，双击 `InvoiceSummary.exe`。
2. 选择完整批次的 PDF 文件夹和目标 `.xlsx` 工作簿。
3. 点击“只读预览”，核对文件名、明细、金额和异常；解决异常后重新预览。
4. 预览通过后点击“执行处理”，清空旧明细并按完整批次重填，等待完成。
5. 等待完成提示，查看金额复核结果和临时文件清理状态。继续处理前重新预览。

**执行会重命名 PDF，清空两表全部旧明细（含品牌、备注）后整批重填；原位更新，不自动创建备份。**

## 必要条件

- Windows 10/11，已安装 Microsoft Excel 桌面版；软件离线运行，无需安装 Python 或 Node.js。
- 完整解压整个软件文件夹，保留 `InvoiceSummary.exe`、`_internal` 和 `recognition`。
- 有文本层的电子 PDF；每次选择完整批次，不支持扫描图片 OCR。目录中没有的旧明细将移除，旧表人工修改不会保留。
- `.xlsx` 含“验收”“领用”两表，以及约定的表头、明细格式行、日期标签和唯一“合计—签字—说明”三行页脚。
- 执行前关闭 Excel 中的目标工作簿；软件和输入文件所在目录须可写。

0.1.2 起，软件默认处理页顶部直接显示“执行步骤”和“必要条件”；“使用说明”页和发布包内的说明文件也优先展示这两项。

## 阶段完成提示

0.1.5 起，操作按钮下方持续显示当前阶段、结果与下一步：蓝色为处理中，绿色为通过，黄色为预览异常或清理提醒，红色为操作未完成。只读预览与执行结束时弹出一次结果提示；关闭后仍可查看页面上的提示条和详细报告。

预览有异常时明确提示暂不能执行，执行失败时显示失败原因；填表成功但临时文件清理未完成时单独提醒。人工校正后的检查只更新页面提示。更换输入或更新规则后，旧的完成提示清除，需要重新预览。

## 人工校正

0.1.3 起，在只读预览中选中明细并点击“人工校正”，或直接双击该行。对照原 PDF 修改产品名称、规格型号、单位、数量、含税金额和生产厂家；单价自动计算。弹窗同时显示原识别值和当前值，支持“打开原发票”和“恢复识别值”。

点击“保存并检查”只更新本次预览；软件重新检查金额、改名碰撞与工作簿模板，通过后才允许执行。校正过的明细会高亮，检查结果记录修改前后值。正式重填使用本次预览及校正后的全部明细。

这是软件本地功能，不修改或训练 skill。只能校正已有明细字段，不能增删明细、改序号或修改票面总额；漏项、多项和整票解析失败仍需改进 skill。数量空白按 1，非空须为有效非零数字；名称、生产厂家不能为空，规格和单位可空。校正后的每票明细合计必须仍与原票面总额逐分一致。

校正只对本次预览有效；重新发起普通预览会重新识别，需要再次校正。执行中断时校正随本机恢复记录保留，核对 PDF 哈希和识别版本后恢复；恢复期间先完成上次运行，再进行新的人工校正。记录不会随软件目录分发。

## 完整批次重填

0.1.4 起，软件每次清空“验收”和“领用”表头之后、合计之前的主表明细内容，再按当前完整 PDF 批次连续重填。主表中的品牌、备注、其他手填内容、批注和超链接一并清除，旧名称或旧金额与识别结果不同不再阻塞。保留表头、格式、其他工作表、签字和说明页脚，按明细数量调整数据区并重新生成单价和合计。

0.1.7 起，清空范围按完整表头的最右列界定，保留主表右侧“第二联：财务报销”等模板内容。侧边文字分写在多个单元格时也保留原位置和样式；增减明细行后仍保留，保存时复验，预览报告显示保留数量。不能安全移动的右侧合并结构或跨主表／侧边的公式区域在预览中停止。旧版本已经删除的文字不会自动从其他工作簿补回，须补回文字或使用完整模板。

0.1.8 起可同步 skill 的 `template_rules.json`。新规则按主表右侧完整标识的实际结束行保留必要空白明细区，不固定为第 13 行；合计在“本次末条明细”和“最低保留行”中较晚者之后。保留空行的样式、边框和行高，空行不填假数据，合计范围包含保留区。预览显示每表最低保留行、必要空行数和合计行。若源模板合计已经位于标识结束行或其上方，停止并提示恢复完整模板，与 skill 一致。

新版默认保留原引擎；在“规则与更新”同步已更新的本机 skill，模板规则才随新快照启用。旧快照及回退到旧版使用原删行行为；没有匹配完整标识时按实际明细收缩。

只读预览只在内存中拟定计划，显示每表旧明细清空数量及本次重填数量，不保存原文件。正式执行使用暂存工作簿及原位替换，然后继续 Excel 字体、重算和逐分验证。即使旧表明细与本次相同，普通预览也可以执行重填；空发票批次、识别异常、金额不符、重名和模板结构问题仍阻塞。

未完成运行保留写表前哈希及写入阶段。两表已写完并完整对应预览时，恢复可跳过重复写表；如果写入阶段记录缺失且工作簿已变化，需要完整对应本次结果，否则停止等待核实。旧版本恢复记录仍可读取。

完整重填是本软件的写表策略，skill 的识别、规范化、折扣及运费处理规则保持对应；未修改 skill 原写表器。

## 功能归属与更新边界

0.1.6 起，在“规则与更新”中默认显示“功能归属”，另有“本次更新结果”和“skill 原始说明”。发布目录附带 `功能归属与更新边界.txt`；界面及该说明均来自软件自身的 `invoice_desktop/policy.py`。

| 分类 | 内容 | 更新方式 |
|---|---|---|
| skill 共享规则 | PDF 识别、字段规范化、折扣与运费、排序与文件名、金额验证，字体／重算和写后金额采集，以及模板最低保留行声明 | 同步兼容的脚本、template_rules.json 及来源说明 |
| 软件独有功能 | 人工校正、执行前清空全部旧明细并整批重填、完成提示、中断恢复、界面操作和便携分发 | 升级软件；skill 同步、导入和回退均保留 |
| 共同约定 | 字段含义、序号、金额精度、表头和三行页脚、日期、单价／合计及脚本输入输出接口 | 变更时检查兼容性，必要时同步升级软件 |

软件流程固定为：**识别 → 可选人工校正 → 重新检查 → 正式执行时清空旧明细并整批重填 → 写后金额核对**。skill 原文作为来源参考，其中的对话回复格式、自动执行方式及增量匹配填表方式不作为软件操作指令。

同步、导入及回退结果显示共享规则的前后版本、受影响功能和保留的软件功能。包含 JSON 模板规则的新包采用清单格式 3，作用范围为 `shared-invoice-rules`，数据、工作簿和模板规则接口版本均为 1；规则文件和声明计入版本哈希。旧格式 1/2 的四文件包及快照仍可读取，保持原删行策略；同步没有模板声明的旧 skill 导出格式 2。

兼容性以软件自带的支持约定为依据，活跃、同步、导入、回退及便携构建都检查相同约定。`write_summary.mjs` 只记录指纹，不随包复制或运行；明确支持原写表器与本次读取 JSON 的写表器指纹。受支持的模板声明更新无需更改软件；未知写表器变化、新策略、新依赖或不兼容接口要求升级软件。软件继续维护人工校正和清空重填。

`template_rules.json` 的 schema 版本 1 支持 `sidebar-label-end` 策略、完整标识列表、忽略标点、单格及同列连续分段排列声明。双方以实际工作表坐标定位，主表边界含合并表头的终列；`label_value_source: literal-cells` 要求右侧为固定值，出现右侧公式则报告坐标并停止，避免使用不确定缓存。双方按该声明解释单元格，不执行 SKILL.md 原文，不存在固定最低行号配置。

检查能够拒绝不支持的声明、已知接口变化及写表组件变化，不能自动理解任意代码或文档的语义。维护者仍须保持规则与脚本对应并验证真实识别场景；软件预览和逐分复核继续保护业务执行。

## skill 更新

识别引擎有独立版本。0.1.1 起，当前规则和回退快照保存在软件文件夹的 `recognition` 目录中。

维护者操作：更新 skill → 打开“规则与更新”并选择整个 skill 文件夹 → 点击“同步本机 skill” → 等待更新完成 → 关闭软件 → 打包整个 `InvoiceSummary` 文件夹。请保留 `InvoiceSummary.exe`、`_internal` 和 `recognition`。

接收方完整解压软件包后直接运行即可使用随包规则，无需绑定 skill 或导入更新包。请在新文件夹完整解压新版，或完整替换旧软件文件夹；只复制 EXE 不会携带规则及依赖。

软件文件夹需可写才能同步或回退规则。维护者的 skill 路径绑定和未完成业务运行记录保存在本机 AppData，按软件目录区分，不包含在分发目录中。软件不会自动绑定接收方电脑的 skill；当随包识别版本变化时，旧绑定失效。

仍可用“导出离线更新包”“导入更新包”单独传递规则。“回退版本”切回上一个识别快照并解除本机来源绑定；再次打包软件目录时会携带回退后选中的版本。

软件采用 skill 的 `invoice_pipeline.py`、`collect_excel_totals.py`、`apply_mixed_fonts_excel.ps1` 和共享 `template_rules.json`；`SKILL.md` 是共享规则来源，软件自身策略以“功能归属”为准。更新时共同维护文档与对应实现。仅改变规则文字会被标记为待适配；未支持的 Node 写表器变化须先适配软件。

开发者导出离线包：

```powershell
python tools/export_update.py --skill C:\path\to\summarize-invoice-pdfs --output C:\path\to\invoice-skill-update.zip
```

更新包检查版本、入口、路径白名单和 SHA-256。新依赖或接口改变需要升级主程序。请只选择可信的 skill 来源；校验和用于完整性检查。

激活前还会检查必需函数的参数、实际依赖加载和预览／改名／金额采集／验证的输出接口。检查只使用临时生成的空输入，不会接触业务文件；接口不兼容时保持当前版本。

如果 Excel 操作或验证中断，再次选择同一批次和工作簿进行只读预览，即可继续未完成流程；重启软件后也有效。恢复期间需保持发票内容和识别版本一致。完成验证后清除恢复记录。

移动明细和页脚时会同步更新原有公式的普通、绝对和跨表引用。涉及动态引用、命名区域等无法安全迁移的结构时，预览会停止并指出原因。

需要增减明细行时，含 Excel 表格、筛选、条件格式、数据验证、透视表、图表、图片或手动分页的工作表会提示调整模板；工作簿或任一工作表的命名区域，以及涉及移动区的重复打印行、冻结窗格和超链接也会阻塞。无需增减行时仍可按原数据区重填。

## 开发与验证

```powershell
python -m pip install -r requirements-build.txt
python -m unittest discover -s tests -v
python main.py --smoke-gui gui-check.json
python main.py --pipeline-smoke C:\path\to\invoice.pdf --output pipeline-check.json
powershell -NoProfile -ExecutionPolicy Bypass -File tools/build.ps1
python tools/package_release.py --directory release/InvoiceSummary
```

流程诊断只处理临时复制的 PDF 和新生成的测试工作簿，原始 PDF 不会修改。诊断报告不要作为发布包资产。

构建时，`tools/prepare_portable.py` 优先保留现有 `release/InvoiceSummary` 中的规则；首次升级才读取旧 AppData 中兼容的规则。只复制规则白名单和清单，不复制个人路径、设置或业务记录。运行中的软件直接使用所在目录的规则，旧 AppData 规则不参与选择。

## 实现

Python/tkinter、pdfplumber、openpyxl 与 Microsoft Excel 自动化。现有 Node 写表器依赖的 OpenAI 内部评估组件不随软件分发，软件使用独立的 openpyxl 写表器执行同一模板约定。openpyxl 的行移动不会自动维护所有相关结构，因此软件明确处理页脚合并、行高、打印区域和总计公式；参考 [openpyxl 行编辑说明](https://openpyxl.readthedocs.io/en/3.1.1/editing_worksheets.html)。打包采用 [PyInstaller 的目录分发方式](https://www.pyinstaller.org/en/stable/usage.html)。
